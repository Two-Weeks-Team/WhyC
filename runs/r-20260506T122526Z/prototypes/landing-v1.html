How it works

Four stages. One agent. No humans-in-the-loop.

The agent owns its own judgment. It decides which companies it can credibly ship. It writes its own evaluation prompt. It iterates until it's right.

01 · Analyze

Read the public posting.

Gemini ADK extracts product hypothesis from the YC blurb + open job descriptions. Outputs a 14-line spec.

02 · Go / No-Go

Decide what to ship.

Cost ceiling $5. Complexity ≤7 iter. IP-safe. Demo-able. Failures get a public "why we passed" card.

03 · Develop

Generate a Next.js scaffold.

Design tokens · 1–2 working APIs · seed data · OpenInference auto-instrumentation throughout.

04 · Deploy

Ship to Cloud Run. Self-improve.

Phoenix MCP queries traces. LLM-as-judge scores spec-fit. Under-spec flows regenerate until convergence.

Methodology

Five things that shouldn't be controversial, but are.

If your agent picks its own winners, it should also be willing to disqualify itself. WhyC does both, in public.

The judge prompt is versioned and public.

You can read /eval/judge_prompt.v1.md. You can compare it to v2 when we change it. You can audit every spec-fit score against the prompt that produced it.

The spec-fit formula is deterministic.

Same trace, same prompt, same score. Phoenix stores the seed. Re-runs reproduce the number. No vibes.

No-Go is a first-class outcome.

Companies WhyC won't touch get a public card explaining why. Hardware-bound, regulated, stealth, over-budget — all surfaced, none hidden.

Self-improvement uses the agent's own audit log.

Phoenix MCP is queried by the agent itself, not by a sidecar. Under-spec flows regenerate. The trace tree shows every iteration.

One stack. No SDK. No CLI. No Slack bot.

A single Next.js + Cloud Run codebase. Two engineers. Thirty-six days. Web-only on purpose — scope is the killer feature too.
